# DoD demo detection catalogue

Generated by `tools/detection_prep.py` from the NAIP Huntsville panorama plus
the hand-authored scenario overlay. See `attribution.txt` for upstream data /
model licensing, and `doc/architecture/sg2-detection-walkthrough.md` for the
viewer's tour of how these artifacts drive the trust story.

Contents (regenerated on first run; `catalogue.json` + `crops/` are
gitignored, `overlay.json` + `attribution.txt` + this README are committed):

- `catalogue.json` — per-object record (panorama AABB `bbox_panorama_px`,
  preserved oriented box `obb_panorama_px`, UTM extent, crop path, label,
  confidence, `world_uid`).
- `crops/*.jpg` — 128×96 thumbnails (20% margin around each AABB), inlined
  as base64 into each detection `Reading` at runtime.
- `overlay.json` — the synthetic storyline objects injected at conf=1.0.

## A note on ground-truth in the crops

Each detection crop is a literal cutout of the panorama — a visible building,
road, or parking lot. A maximally-paranoid reading of the threat model might
ask whether shipping these crops lets a compromised peer "see the world"
without actually flying its sensor.

It does not introduce a new leak: **the panorama is already the simulator's
complete world model.** Every peer's `DetectionSource` intersects its FOV with
the same catalogue derived from that one panorama; the crop is just the slice
of imagery the peer's FOV would have captured anyway. A compromised peer gains
nothing from the crop bytes that it couldn't already derive from its own FOV
geometry over the shared world model. The crops exist so the *operator* (via
the inspector drawer) can see the visual evidence behind a peer's reported
detection — including the MQ-800's compound-bravo crop sitting in its
compound-alpha panel, which is the whole point of the deception story.

In short: the crops surface ground truth to the human analyst, not new
capability to a compromised node. (Open question §9.8 in
`STRETCH_GOAL_2_DETECTION_PLAN.md`, resolved.)
